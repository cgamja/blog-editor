# ADR-001. 에디터는 별도 백오피스 서비스이고, 사이트는 빌드 시 공개 API에서 HTML을 받는다

- 날짜: 2026-09-22
- 상태: 승인됨
- 원천: 설계 문서 D2 · D6 (2026-09-21 방향 전환)

## 문제 (맥락)

블로그 글을 markdown 파일로 레포에 커밋하는 지금 방식(사이트 ADR-002)은 비개발자가 쓰기 어렵고, 꾸미기(글씨체 · 스티커 · 움직임)와 AI가 쓴 초안을 받을 자리가 없다. 에디터를 어디에 두고 사이트와 어떻게 이어야 하는가.

## 결정

- 에디터는 별도 레포(`blog-editor`) · 별도 도메인(`editor.simsimeestudio.com`)의 백오피스다. 1단계는 본인용, 2단계에 외부 사용자를 받는다(ADR-007).
- 두 레포 사이의 계약은 **공개 조회 API 하나**(`GET /public/posts`)다. 응답은 메타 + 렌더된 HTML + 본문용 CSS 주소. 사이트는 이 응답을 자기 zod로 검증하고 HTML을 허용 목록으로 sanitize한다. 초안이 섞이거나 API가 실패하면 빌드를 실패시킨다.
- 발행 시 에디터 서버가 Netlify build hook을 호출한다. 서버가 가진 외부 권한은 이것뿐이다.
- 사이트 레포에서는 이 결정이 ADR-002(markdown 파이프라인)를 부분 대체한다 — 사이트 레포에 별도 ADR로 적는다.

## 버린 대안

- **npm 공유 패키지(스키마 · 렌더러)를 사이트에 설치**: 렌더러가 두 곳에서 돌고 버전을 맞춰야 한다. 새 블록마다 사이트도 배포해야 한다. 「에디터가 별도 플랫폼인데 왜 사이트가 코드를 설치하나」는 질문에 답이 없었다(2026-09-21 폐기).
- **에디터가 사이트 레포에 커밋(GitHub 토큰)**: 서버가 레포 쓰기 권한을 가진다. 새어 나가면 사이트 전체가 위험하다.
- **사이트 레포 안에 에디터 동거**: 정적 사이트(JS 0, SEO 최우선)에 로그인 · contentEditable · 서버가 들어온다. 관심사가 다르다.

## 감수한 트레이드오프

- 발행부터 공개까지 빌드 시간 1~2분. 방문자 요청마다가 아니라 빌드 때 한 번이라 감수한다.
- 사이트는 에디터 서버에 빌드 시 의존한다. 단 API가 죽어도 이미 공개된 사이트는 그대로다(이전 배포 유지).
- 렌더된 HTML을 받으므로 사이트가 글 내부 구조를 모른다 — 사이트 쪽에서 블록 단위 재가공은 못 한다. 필요해지면 API가 JSON도 같이 주면 된다.

## 재검토 조건

- 사이트가 글을 블록 단위로 다뤄야 할 때(예: 글 안 특정 블록만 홈에 노출).
- 배포 크레딧(월 300, 배포당 15)이 모자랄 정도로 발행 빈도가 오를 때 — 그때는 ISR/서버 렌더 검토.
