# ADR-030. 글 내용 SEO는 규칙 검사기가 경고로 알리고 저장 · 발행을 막지 않는다 — 핵심 검색어는 저장 전용, 수정일은 서버가 올린다

- 날짜: 2026-09-25
- 상태: 제안됨 (#138, PR 머지 = 승인)
- 원천: 이슈 #138 · 블로그 자동화 계획(https://claude.ai/artifact/LtgYgQ8UacAiGEegBKnBLC) · adr-007(서비스가 LLM을 부르지 않는다) · adr-020(선택 필드 추가는 schemaVersion 유지)

## 문제 (맥락)

2026-09-25 사용자 방향으로 글은 AI가 쓰는 게 기본이 되었다. 기술 SEO는 사이트가 이미 자동으로 챙긴다. canonical · robots · OG · `BlogPosting` JSON-LD · sitemap이 그것이다. 빠진 것은 **글 내용** SEO다.

- 이미지 설명(alt)
- 소제목 구조
- 검색 결과에 보이는 제목 · 설명 길이
- 첫 문단이 바로 답하는지
- 핵심 검색어
- 내부 링크

AI는 긴 대화에서 글쓰기 가이드를 잊는다. 사람도 발행할 때 같은 기준을 봐야 한다. 그리고 발행 글을 고쳐도 `updated`가 그대로라서 사이트의 `dateModified`가 오래된 날짜로 남는다.

## 결정

- **규칙 검사기**: content-schema `checkSeo`는 AI · 네트워크를 부르지 않는 순수 함수다.
  - adr-009 엣지를 새로 만들지 않는다. api와 web이 이미 content-schema에 의존하므로 두 곳이 같은 함수를 쓴다.
  - 발견은 등급 must · should · info와 위치(메타 칸 · 블록 번호 · 글 전체), 고칠 방법을 담는다.
  - 기준 숫자는 `seo.constants.ts`에 근거와 함께 둔다.
- **경고일 뿐 막지 않는다**:
  - MCP 쓰기 도구는 저장한 뒤 응답에 `seo`를 싣는다. AI가 그것을 보고 스스로 다시 고친다. 형식 오류 메시지가 이미 쓰는 되먹임 고리와 같다.
  - 에디터는 발행 확인 대화상자에 점검 목록을 보여 주되 발행 버튼을 남긴다.
  - MCP 서버 `instructions`가 연결할 때 "가이드 먼저, `seo` must부터 고친다"를 알린다.
- **핵심 검색어 `keyword`**: 글 정보의 선택 칸이다. 저장 전용이라 공개 조회 · 목록 요약에 싣지 않는다. schemaVersion은 1 그대로다(adr-020 선례).
- **수정일**: `PUT /api/posts/:slug`가 판단한다. 저장된 판과 새 판이 모두 발행 상태이고 제목 · 설명 · 문서가 바뀌었으면 `updated`를 오늘(Asia/Seoul)로 둔다. 내용이 같으면 **저장된** `updated`를 지킨다 — 편집 화면 폼에 남은 옛 값이 서버가 올린 값을 되돌리지 못한다. 편집 화면은 `updated`를 스스로 채우지 않는다(원래 발행 글을 저장할 때마다 브라우저 시간대의 오늘을 넣던 것을 지웠다).
  - 클라이언트가 아니라 서버가 정하는 이유가 있다. 발행 글을 쓰는 길이 이 PUT 하나이고(MCP는 발행 글을 못 쓴다), 조건부 저장이 확인하는 판을 서버만 확실히 안다.

## 버린 대안

- **검사 must면 저장 · 발행을 거부**: SEO 기준은 휴리스틱이다. 구글도 글자 수 · 제목 길이에 고정 규칙이 없다고 한다([Search Central: title links](https://developers.google.com/search/docs/appearance/title-link), [snippets](https://developers.google.com/search/docs/appearance/snippet)). 짧은 공지 글처럼 규칙에 안 맞는 정상 글이 발행을 못 하게 된다. 형식(닫힌 집합)은 막고, 품질은 알린다.
- **LLM으로 점수 매기기(서비스 안)**: adr-007에 어긋난다(비용 · 서비스가 모델을 부름). 판단이 필요한 깊은 평가는 사용자가 Claude Code에서 claude-seo로 따로 한다.
- **검사기를 새 패키지 `content-seo`로**: 엣지 표 · 린트 · 경계 테스트를 함께 고쳐야 한다(adr-009). 검사기는 zod 스키마 타입만 읽는 순수 함수라 content-schema 안에 둬도 ProseMirror를 모른다는 경계가 지켜진다.
- **`updated`를 에디터 화면이 채움**: 자동 저장 · 발행 · 충돌 되살리기가 각자 판단해야 한다. 판이 맞는지는 서버 조건부 저장만 안다.
- **keyword를 공개 응답에도 싣기**: 사이트가 쓸 곳이 없다(meta keywords는 구글이 쓰지 않는다). 공개 계약은 strict라 추가하면 두 레포 계약이 바뀐다.

## 감수한 트레이드오프

- 기준 숫자(제목 10~35자 · 설명 40~120자 · 첫 문단 200자 · 본문 500자)는 한국어 검색 결과 화면을 보고 잡은 작업값이다. 공식 수치가 아니다. 그래서 발견은 should · info로 둔다.
- 에디터의 중복 검사는 제목만 한다. 목록 API 요약에 설명이 없어서다. 설명 중복은 MCP(저장소 전체를 읽는다)에서만 잡힌다.
- MCP 쓰기 응답이 길어진다(발견 목록). AI 토큰을 조금 더 쓴다.
- 처음 발행한 날은 `updated`를 두지 않는다. 같은 날 여러 번 고치면 `updated`가 `date`와 같을 수 있다.

## 재검토 조건

- 실제 글에서 발견이 계속 무시되거나 오탐이 잦을 때: 기준 숫자나 등급을 다시 본다.
- 사이트 검색 성과(서치콘솔)로 어떤 규칙이 효과가 없다고 확인될 때.
- 목록 API에 설명이 들어가게 될 때: 에디터 중복 검사를 넓힌다.
