# ADR-005. 인프라는 AWS 서버리스(S3 · CloudFront · API Gateway · Lambda), WAF 없이 긴 비밀번호와 라우트 스로틀로 지킨다

- 날짜: 2026-09-22
- 상태: 승인됨
- 원천: 설계 문서 D7 · D8 · D10 · D12 · 04 Infra

## 문제 (맥락)

하루 한 번 쓰는 백오피스에 서버 상시 비용을 내고 싶지 않다. 그러나 로그인이 있는 서비스를 공개 인터넷에 두면 무차별 대입과 「돈이 새는」 공격(denial-of-wallet)을 막아야 한다. 그리고 개발 초반에 클라우드 세팅에 시간을 쓰면 정작 에디터를 못 만든다.

## 결정

- **AWS 서버리스**: S3(화면 정적 파일 + 글 + 이미지) · CloudFront(SPA fallback은 CloudFront Function으로 — 배포 단위 「403/404 → index.html」은 API 오류까지 삼키므로 쓰지 않는다) · API Gateway HTTP API · Lambda(Hono) · SSM Parameter Store(비밀값) · DynamoDB(계정 · OAuth). 화면과 API가 같은 도메인이라 CORS가 없다. IaC(SST · CDK · SAM 중 스파이크에서 선정)로만 만든다. 예상 비용 월 $0~1.
- **WAF는 쓰지 않는다.** 대신: 비밀번호 관리자가 만든 **20자 이상 무작위 비밀번호** + scrypt 해시(시도당 수십 ms) + 실패 응답 고정 지연 + **API Gateway 라우트 스로틀**(`/api/session`에 초당 1~2회 · burst 5 — 시도 속도와 비용이 함께 묶인다) + AWS Budgets 월 $5 알림. Lambda 예약 동시성은 쓰지 않는다(새 계정 동시성 한도 10에서 예약이 거부된다).
- 세션은 HMAC 서명 쿠키 `httpOnly · Secure · SameSite=Strict`. 비밀값은 SSM에서 Lambda로만, 클라이언트 번들에는 아무것도 없다.
- **로컬 우선**: M0~M3은 클라우드 없이(Hono를 Node로, `FilePostStore`, Vite 프록시). AWS는 M4에서. 단 M0 스파이크에서 최소 스택을 올려 확인하고 철거한다.

## 버린 대안

- **Netlify/Vercel Functions에 서버까지**: 편하지만 Hono가 웹 표준이라 어디로든 옮겨진다는 점을 살려 AWS를 직접 배운다(포트폴리오 문제 중 하나). 옮길 길은 열려 있다.
- **EC2/컨테이너 상시 서버**: 하루 한 번 쓰는 서비스에 월 $5~20.
- **WAF 도입**: 월 $5+ 고정 비용. 계정이 하나이고 비밀번호가 길면 방어의 핵심은 속도 제한이 아니다.
- **Cognito 로그인**: 1단계 계정 1개에 과하다. 2단계 외부 사용자에서 재검토.

## 감수한 트레이드오프

- 이 방어는 **비밀번호가 정말 길고 무작위일 때만 성립한다.** 기억하기 쉬운 비밀번호를 쓸 거면 DynamoDB 카운터(5회 실패 → 15분 잠금)를 붙인다. 2단계에 외부 사용자가 오면 이 전제가 깨지므로 그때 다시 본다.
- Lambda 콜드 스타트 수백 ms. 백오피스라 감수한다.
- AWS 세팅 · IAM · IaC 학습 비용. 일정에서 M4 한 주를 통째로 잡았다.

## 재검토 조건

- 2단계 외부 사용자 공개 시(비밀번호 전제 · 요청량 · 계정별 한도).
- 월 비용이 $5 알림에 걸릴 때.
- 스파이크에서 라우트 스로틀이 429를 내지 않거나 CloudFront Function으로 SPA fallback이 안 될 때.
