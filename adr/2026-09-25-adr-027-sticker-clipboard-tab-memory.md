# ADR-027. 복사한 스티커는 클립보드 HTML이 아니라 탭 메모리 + 표식으로 되살린다

- 날짜: 2026-09-25
- 상태: 승인됨

## 문제 (맥락)

ProseMirror는 에디터 안 복사도 클립보드에 HTML로만 싣는다(`data-pm-slice`에는 열린 깊이 · 조상만 — prosemirror-view 1.42.5 `serializeForClipboard`). 스티커는 파싱 규칙이 읽지 않고, 붙여넣기 정규화(editor-paste)는 스티커를 늘 지운다. 그래서 스티커 있는 블록을 복사 · 붙여넣기하거나 잘라 옮기면 스티커가 사라진다(#65). 스티커는 닫힌 집합(adr-008)이라, 클립보드 HTML의 속성은 다른 앱 · 다른 탭 · 사람이 만든 HTML에서도 올 수 있는 입력이다.

## 결정

- 복사할 때(`transformCopied`) 조각의 최상위 블록마다 종류 · 글자 · 스티커를 **탭 메모리**(모듈 하나, 최근 4개)에 둔다. 스티커가 없으면 기억하지 않는다.
- 클립보드 HTML 첫 블록 요소에는 **추측할 수 없는 표식**(`data-blog-editor-clip`, Web Crypto 128비트 난수)만 단다(`clipboardSerializer`).
- 붙여넣을 때(`transformPastedHTML`) 표식이 메모리에 있고, 조각의 최상위 노드 수 · 종류 · 글자가 같으며, 최상위 자리일 때만 스티커를 되살린다(`transformPasted`, 정규화 뒤). 되살린 값도 닫힌 집합으로 다시 거른다.
- 세 번 클릭 · 끌기 · Shift+화살표로 블록 글자 전체를 고른 복사는 양끝이 열린 조각이라, 붙이면 글자만 자리 블록에 합쳐지고 속성은 자리 블록 것이 남는다(prosemirror-transform 1.12.1 `replaceRange`). 그래서 복사할 때 열린 끝 블록이 원래 블록 글자 전체인지 기록하고, 붙일 자리가 빈 최상위 글자 블록(글자 · 스티커 없음)일 때만 조각의 양끝을 닫아 복사한 블록이 그 자리를 대신하게 하고, 커서를 붙인 블록 글자 끝에 둔다(`handlePaste`로 직접 붙인다 — 기본 붙여넣기는 닫힌 블록 뒤 다음 블록 맨 앞에 커서를 둔다, prosemirror-state 1.4.4 `selectionToInsertionEnd`). 글자를 고른 자리는 닫지 않는다 — 자리 블록의 종류 · 스티커 · 꾸밈이 말없이 사라지고, 복사 원본에 스티커가 있느냐에 따라 결과가 갈린다. 복사 쪽(`transformCopied`)에서 닫지 않는 이유: 문장 안에 붙이면 글자로 들어가던 것이 블록 삽입으로 바뀐다.
- 붙인 결과 문서가 글 하나 스티커 상한(12)을 넘으면 붙인 쪽 스티커를 뒤에서부터 뺀다. 결과 문서로 세므로 잘라내기 이동은 걸리지 않는다. 뺀 것은 알리지 않는다(조용히) — 알림 자리가 에디터 코어에 없다.

## 버린 대안

- **스티커를 HTML `data-*` 속성으로 싣고 파싱 규칙이 읽기**: 가장 단순하지만 외부 HTML이 같은 속성을 흉내 내면 스티커가 들어온다. 닫힌 집합 검증은 값만 지키고 "스티커는 에디터 밖에서 오지 않는다"는 경계를 지키지 못한다.
- **붙여넣은 조각을 마지막 복사와 글자로만 대조(표식 없음)**: 에디터에서 복사해 다른 앱을 거쳐 같은 글자를 다시 붙이면 스티커가 되살아난다. 출처를 가를 수 없다.
- **`handlePaste`에서 붙여넣기를 가로채 메모리의 조각을 그대로 넣기**: 브라우저가 준 HTML과 다른 내용이 들어갈 수 있고, 정규화 · 자리 판단을 다시 만들어야 한다.
- **커스텀 MIME(`application/x-…`)으로 조각 JSON 싣기**: prosemirror-view의 복사 · 붙여넣기 흐름 밖이라 copy · paste 이벤트를 직접 다뤄야 하고, 브라우저마다 커스텀 타입을 클립보드에 남기는 정도가 고르지 않다(확인하지 않았다).

## 감수한 트레이드오프

- 다른 탭 · 새로 고침 뒤 · 다른 앱을 거친 붙여넣기에서는 스티커가 사라진다(지금과 같음).
- 되살아나는 복사: 블록 전체가 닫힌 조각(⌘/Ctrl+A · 블록 노드 선택 · 여러 블록 선택의 가운데 블록), 블록 글자 전체를 고른 열린 끝 블록을 빈 최상위 글자 블록에 붙일 때. 되살아나지 않는 복사: 블록 글자 일부만 고른 열린 끝 블록, 남의 글자 가운데에 섞이는 열린 끝 블록(누구의 스티커인지 모호), 글자를 고른 자리에 붙이는 열린 끝 블록(자리 블록 유지), 목록 · 인용 · 콜아웃 안에 붙일 때.
- 열린 끝 블록을 빈 글자 블록에 붙이면 그 빈 블록의 종류 · 꾸밈은 복사한 블록의 것으로 바뀐다(빈 제목에 붙이면 문단이 된다) — 스티커를 되살릴 때만 조각을 닫으므로 스티커 없는 복사는 지금과 같다.
- 에디터 안 Alt 끌어 복사는 내부 조각이 표식 없이 와서 지금처럼 스티커가 사라진다.
- 표식은 클립보드에 적혀 탭 밖으로 나가지만, 값을 알아도 쓸 곳은 그 탭의 메모리뿐이다.
- 상한 초과로 뺀 스티커를 사용자에게 알리지 않는다.

## 재검토 조건

- 다른 탭 · 다른 글 창 사이 스티커 복사가 필요해질 때(예: 두 창 편집) — 그때는 커스텀 MIME이나 서버 보관을 다시 본다.
- prosemirror-view가 클립보드에 조각 JSON을 싣는 공식 훅을 낼 때.
- 상한 초과 알림 자리(토스트 등)가 에디터에 생길 때.
