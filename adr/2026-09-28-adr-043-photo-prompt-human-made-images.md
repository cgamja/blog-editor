# ADR-043. 이미지는 사람이 Midjourney 등으로 만들고, AI는 사진 자리에 영어 이미지 프롬프트를 남긴다 — ADR-029 대체

- 날짜: 2026-09-28
- 상태: 제안됨 (#155, PR 머지 = 승인)
- 원천: 이슈 #155 · 사용자 결정 2026-09-28 · adr-029(AI 이미지는 Codex CLI로 — 이 ADR이 대체) · adr-033(사진 자리 · 에디터 전용 설명) · adr-039(여러 블록 바꾸기의 설명 옮기기) · adr-007(서비스는 모델을 부르지 않는다 · AI는 초안만) · adr-020(추가만이면 schemaVersion 유지)
- 대체: ADR-029 전체. ADR-029가 당겨 온 "AI 이미지 생성은 1단계"를 거두고, adr-007의 "이미지는 사람이 올린다"로 돌아간다.

## 문제 (맥락)

ADR-029는 `/blog-write`가 이미지를 공식 Codex CLI(`codex exec` + `$imagegen`, ChatGPT 구독 한도 안)로 만들게 정했다. #155에서 구현하려고 조사해 보니 그 길이 막혀 있었다(2026-09-28).

- **ChatGPT 무료 플랜은 Codex 이미지 생성을 쓸 수 없다.** ADR-029는 "Free에도 Codex가 들어 있고 한도가 작을 뿐"으로 적었지만, 이미지 생성은 무료 플랜에서 막혀 있다.
- **사용자는 유료 계정이 없고, 만들 계획도 없다.** Codex 유료 · API 키 모두 추가 비용이다.
- **Claude는 사진 같은 이미지를 만들지 못한다.** SVG 같은 도식은 그릴 수 있지만 사진 · 일러스트 품질은 아니다.

그래서 이미지는 사람이 만든다. 사용자는 Midjourney 등 이미지 도구를 직접 쓰기로 했다(사용자 결정 2026-09-28). 그런데 지금 사진 자리(adr-033)에는 한국어 설명 한 줄뿐이다. 설명은 대체 글자(alt)의 기본값이기도 해서 이미지 도구용 영어 프롬프트(스타일 · 조명 · 구도)를 겸하면 alt가 망가지고, 사람이 매번 설명을 보고 프롬프트를 새로 써야 한다.

## 결정

- **AI는 이미지를 만들지 않는다.** `/blog-write`는 사진이 필요한 곳에 사진 자리를 두고, 사람이 그 프롬프트로 이미지 도구에서 만들어 에디터에서 채운다. 서비스는 여전히 어떤 모델도 부르지 않는다(adr-007).
- **사진 자리에 에디터 전용 `prompt`(영어 이미지 프롬프트)를 둔다.**
  - 문서: `photoPlaceholder.attrs.prompt` · `image.attrs.prompt` 선택 속성. 한 줄 · 앞뒤 공백 없음 · 1000자 이내(`PROMPT_MAX_LENGTH`, 설명 `briefSchema`와 같은 모양). 선택 속성 **추가**뿐이라 기존 문서가 모두 유효하므로 **schemaVersion은 1 그대로**다(adr-020).
  - markdown: `:::photo` 안 둘째 문단(설명과 빈 줄로 나뉜)이 `prompt:`로 시작하면 그 뒤 글이 프롬프트다. 직렬화도 같은 모양(설명 · 빈 줄 · `prompt: …`)으로 돌아온다. 틀린 모양 · 빈 프롬프트 · 1000자 초과는 "사진 자리 …" 검사 메시지로 알린다.
  - 공개되지 않는다: `publicDocOf`가 그림의 `prompt`를 빼고(사진 자리는 이미 통째로 빠진다), 렌더러는 어느 속성에도 싣지 않는다.
  - 사진을 채우면 프롬프트도 설명처럼 그림에 남는다(나중에 사진을 다시 만들 때 참고). 그림을 사진 자리로 되돌리면 다시 사진 자리로 간다. 그림의 프롬프트는 설명과 같이 markdown에 자리가 없다(`losses`의 `imageBrief`에 함께 센다). 여러 블록 바꾸기가 그림을 덮을 때는 설명과 함께 같은 src 그림으로 옮긴다(adr-039).
  - 불변식: 그림의 설명과 프롬프트는 서로 독립이다(설명을 지워도 프롬프트는 남는다). 에디터 DOM에서 따로 읽고, 부분 고치기는 둘 중 하나라도 있는 그림을 옮길 대상으로 보고 둘을 한 묶음으로 옮긴다.
- **편집 화면:** 사진 자리 도구줄에 「이미지 프롬프트」(보고 고치기 — Enter로 적용)와 「프롬프트 복사」를 둔다. 복사는 사진 자리 비율이 있으면 끝에 ` --ar W:H`를 붙인다(이미 `--ar` · `--aspect`가 있으면 붙이지 않는다). 프롬프트가 남은 그림에서도 같은 칸으로 본다.
- **스타일:** ADR-029의 글 종류별 스타일 표와 "아이 · 가족 인물은 늘 일러스트" 규칙은 `/blog-write`가 프롬프트를 쓸 때 그대로 쓴다. 글당 사진 자리 기본 4곳도 그대로다.
- ADR-029의 Codex 흐름(`codex exec` · `sips`로 줄이기 · 연결 토큰 이미지 올리기 · 캡션 "AI로 만든 그림" 자동 부착)은 버린다. 캡션은 사람이 이미지를 채운 뒤 에디터에서 정한다.

## 버린 대안

- **Codex 유료 플랜(Plus 이상):** ADR-029 흐름이 그대로 돈다. 하지만 사용자는 유료 계정이 없고 이 용도로 구독할 생각이 없다.
- **OpenAI(또는 Gemini · FLUX) API 키:** 자동화는 가장 매끄럽다. 하지만 장당 과금이 생기고, ADR-029에서도 사용자 결정으로 뺀 길이다.
- **로컬 오픈소스 모델(mflux 등 Apple Silicon용 FLUX):** 비용은 0이다. 하지만 모델 내려받기 · 메모리 · 생성 시간이 크고, 품질 · 아이 이미지 안전성을 우리가 관리해야 한다. 에이전트가 무거운 로컬 도구에 묶인다.
- **Claude가 SVG로 그린다:** 도구가 하나로 끝난다. 하지만 도식 수준이라 사진 · 일러스트를 바라는 글에 맞지 않는다.
- **ChatGPT 웹을 브라우저 자동화로 조작한다:** 무료 플랜으로 이미지를 얻을 수 있다. 하지만 약관이 자동화된 접근을 막고, 화면이 바뀌면 깨지며, 계정이 위험하다.
- **설명(brief)을 영어 프롬프트로 쓴다:** 속성이 하나로 끝난다. 하지만 설명은 alt 기본값이라 한국어 독자 · 스크린 리더에 영어 프롬프트가 나가게 된다.

## 감수한 트레이드오프

- **사람 손이 든다:** 글마다 사진 자리 수만큼 사람이 이미지 도구에서 만들고 올려야 발행할 수 있다. 「프롬프트 복사」로 옮겨 적는 일은 줄였다.
- **도구 선택은 사람 몫이다:** 프롬프트는 Midjourney 문법(`--ar`)을 기준으로 붙인다. 다른 도구에 붙여 넣을 때는 끝의 `--ar …`를 사람이 지워야 할 수 있다.
- **속성이 하나 늘었다:** 사진 자리 · 그림에 에디터 전용 칸이 둘(설명 · 프롬프트)이 되어 공개 문서 · 직렬화 · 부분 고치기에서 함께 챙겨야 한다. 한 곳(`publicDocOf` · `serializeMarkdown` · `carryBriefs`)에서 같이 다룬다.
- **에디터 밖으로 복사하면 따라 나간다:** 에디터에서 그림 · 사진 자리를 복사해 다른 앱에 붙이면 figure의 `data-prompt` · `data-brief`가 HTML 클립보드로 함께 나간다(ADR-033의 `data-brief`와 같은 비용). 에디터 안 복사 · 붙여넣기에서 둘이 따라오게 하려고 감수한다.
- **빈 줄 하나가 문법이다:** 설명과 `prompt:` 사이 빈 줄을 빠뜨리면 프롬프트가 설명(공개 alt의 기본값)에 붙으므로, 설명 문단의 어느 줄이든 `prompt:`로 시작하면 실패로 막는다. 설명이 글자 그대로 `prompt:`로 시작하면 직렬화가 `prompt\:`로 이스케이프한다.
- **채운 그림의 프롬프트는 markdown으로 왕복하지 않는다:** 설명과 같다. 글 전체 markdown으로 다시 저장하면 사라진다(`losses`가 알린다).

## 재검토 조건

- 사용자가 유료 이미지 생성 수단(Codex 유료 · API 키)을 갖게 될 때: ADR-029 흐름을 다시 본다.
- Claude나 무료 공식 도구가 사진 · 일러스트 수준 이미지를 만들 수 있게 될 때.
- 사진 자리를 채우는 사람 손이 발행을 자주 막을 때.
- 서비스가 외부 사용자에게 열릴 때(2단계): 이미지 도구 연동을 다시 본다.
