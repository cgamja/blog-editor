# ADR-036. 할 일 목록은 원문으로 읽고, 공개 HTML은 disabled 체크 칸, 에디터는 CSS 체크 칸으로 그린다

- 날짜: 2026-09-25
- 상태: 제안됨(PR 머지 = 승인)

## 문제 (맥락)

adr-028 3절은 할 일 목록의 스키마 모양(`listItem.attrs.checked`)만 정했다. 공개 HTML 마크업 · 접근성 · 에디터 동작은 #132로 미뤘다. 할 일 목록은 GFM 문법이지만 우리 markdown-it 설정에는 플러그인이 없다. 플러그인을 더하면 새 의존성이다(LIBRARY 게이트). 에디터에서는 체크 칸을 누를 수 있어야 한다. 그런데 에디터는 지금까지 NodeView 없이 toDOM만 쓴다(decoration-visible). 체크 칸이 글 흐름 안에 들어가면 한글 조합 · 커서와 부딪힐 수 있다.

## 결정

1. **읽기**
   - markdown-it core 규칙 하나(`task-list.ts`)로 읽는다. 목록 항목 첫 문단 인라인의 **원문**(`inline.content`)이 `[ ]` · `[x]` · `[X]` + 공백 + 글로 시작하면 할 일이다.
   - 첫 글자 토큰에서 원문 표지 길이만큼 떼고, 항목 토큰 meta에 체크 여부를 싣는다.
   - 원문으로 판정하므로 이스케이프한 `\[ ] 글`은 글자로 남는다.
   - 표지만 있고 글이 없는 항목(`- [ ]`)은 거부한다. 빈 항목은 직렬화에서 빠지므로(losses) markdown으로 나를 수 없다.
2. **쓰기**: `- [ ] ` · `- [x] `로 쓴다. 보통 항목의 `[x] 글자`는 이미 대괄호를 늘 이스케이프해서(`\[x\]`) 할 일로 읽히지 않는다.
3. **공개 HTML**
   - `<li class="post-task"><p><input type="checkbox" disabled [checked] aria-label="완료">글</p></li>`로 낸다.
   - 네이티브 체크 칸이라 스크린 리더가 체크 상태를 읽는다. `disabled`라 독자는 바꿀 수 없다.
   - 이름은 늘 "완료"다. 체크 칸 이름을 항목 글에 묶지 않는다. `<label>`로 감싸면 글 안 링크를 누를 때 체크 칸으로 샌다.
4. **에디터**
   - `li[data-checked="true|false"]`로 낸다. 체크 칸은 CSS 가상 요소(`::before` · `::after`)로 그린다. NodeView · 위젯 데코레이션을 두지 않는다.
   - 누르기는 `taskToggle` 플러그인이 받는다. 대상은 `handleDOMEvents.mousedown`에서 **항목 요소 자신**이고, 누른 곳이 글 문단 왼쪽일 때만 받는다. 이때 기본 동작을 막고 `toggleTaskItem(pos)`를 부른다.
   - 조합(IME) 중에는 받지 않는다.
   - 입력 규칙은 `[ ] ` · `[x] `다. Enter로 나눈 새 항목은 체크하지 않은 할 일이다.

## 버린 대안

- **markdown-it-task-lists 등 플러그인**: 새 의존성이다. 우리에게 필요한 일은 표지 떼기와 meta 싣기 둘뿐이다. 플러그인은 HTML 렌더용 속성(class · input 토큰)까지 만들어 check.ts가 알아야 할 토큰이 는다.
- **자식 텍스트 토큰으로 표지 판정**: markdown-it의 text_join이 이스케이프(`\[`)를 글자로 합친 뒤라, `\[ ] 글`과 `[ ] 글`을 구별할 수 없다.
- **공개 HTML을 CSS만으로(체크 칸 없이 `data-checked` + 숨긴 글자)**: 스크린 리더에 체크 상태가 "체크 칸"으로 읽히지 않는다. 숨긴 글자는 번역 · 복사에 섞인다.
- **공개 HTML 체크 칸 이름을 항목 글로(`<label>`)**: 글 안 링크를 누르면 label 동작으로 체크 칸에 초점이 간다(disabled라 바뀌지는 않지만 동작이 어긋난다).
- **에디터 NodeView(TipTap TaskItem 방식)**: 생명주기(update · ignoreMutation · stopEvent)를 우리가 맡아야 한다. 에디터의 "toDOM만" 원칙도 깬다.
- **에디터 위젯 데코레이션(체크 칸 요소를 글 앞에 끼움)**: 글 문단 맨 앞에 위젯이 있으면 커서 · 한글 조합이 위젯 옆에서 어긋나는 브라우저 차이가 있다. 가상 요소는 contenteditable 글 흐름 밖이다.

## 감수한 트레이드오프

- 에디터 체크 칸은 키보드 초점을 받지 않는다. 키보드로는 「바꾸기」 · 입력 규칙으로 할 일을 만들 수 있지만, 체크를 켜고 끄는 단축키는 없다(후속).
- 누르기는 "항목 요소 + 글 왼쪽" 판정에 기댄다. CSS가 글머리 자리를 항목 안으로 당겨야(`margin-left` · `padding-left`) 그 자리가 항목 요소가 된다. CSS를 바꾸면 e2e가 잡는다.
- 공개 HTML에 `input`이 새로 나간다. 사이트 레포 sanitizer가 `li.post-task`와 `input[type=checkbox][disabled][checked][aria-label]`을 받아야 한다(표 · `br`과 함께 후속).
- `aria-label="완료"`는 한국어 고정이다. 글이 다른 언어면 맞지 않는다(블로그는 한국어뿐).

## 재검토 조건

- 에디터에서 키보드로 체크를 바꿔야 할 때(단축키 · 포커스 가능한 체크 칸).
- 사이트 sanitizer가 `input`을 받지 못하는 사정이 생길 때(CSS만 대안으로 돌아간다).
- 글이 여러 언어가 될 때(체크 칸 이름).
