# ADR-008. 꾸미기는 닫힌 집합이고, 스티커는 페이지 좌표가 아니라 블록 기준 비율로 저장한다

- 날짜: 2026-09-22
- 상태: 승인됨
- 원천: 설계 문서 D14 · 3-13 꾸미기 · 3-14 화면 디자인 (2026-09-21)

## 문제 (맥락)

글을 사이트 랜딩처럼 꾸미고 싶다 — 블록 옮기기 · 이미지 크기 조절 · 글씨체(Pretendard · Jua · Gaegu) · 스티커 · 움직임. 「스티커를 아무 데나 놓고 싶다」와 「성능이 많이 중요하다」(SEO 최우선 사이트)가 부딪친다. 자유 배치(페이지 좌표)는 화면 폭이 바뀌면 깨지고, 임의 CSS는 검증할 집합이 열린다.

## 결정

- **닫힌 집합**: 블록 속성 `font`(3종 enum) · `motion`(enum) · `width`(% 범위) · `stickers[]`(스티커 ID enum + `x` · `y` · `size`(%) · `rotate`(도), 글 하나에 최대 12개). 임의 CSS · 클래스 · 페이지 좌표는 스키마에 자리가 없다.
- **블록 기준 비율**: 스티커를 아무 데나 끌어다 놓으면 **가장 가까운 블록**에 붙고 그 블록 기준 %로 저장된다. 블록을 옮기거나 지우면 스티커도 따라간다. 좁은 화면에서는 본문 폭 안으로 당겨 넣는다.
- HTML에는 클래스와 `data-*` 속성만 나가고 실제 모양은 **본문용 CSS 한 파일**이 입힌다(공개 API가 주소를 준다). 새 스티커 · 움직임을 더해도 사이트는 배포할 것이 없다.
- 움직임은 **CSS 스크롤 애니메이션**(`animation-timeline: view()`)으로 transform/opacity만. `prefers-reduced-motion` 존중. JS 0.
- 성능 기준: 스티커 장당 ≤20KB WebP · lazy loading · 크기 속성 명시. 본문 글꼴은 Pretendard 고정, Jua/Gaegu는 고른 블록에만 쓰고 글 본문 글자로 서브셋한다(한글 글꼴 하나가 1~2MB라 **글꼴이 가장 무거운 항목**이다). Lighthouse CI: 꾸미기를 최대로 쓴 픽스처 글이 기준선 아래면 실패. 기준선은 M0에서 측정.
- 스티커 이미지는 사이트의 기존 두들 9종을 그대로 쓴다. 사용자가 올리는 스티커는 2단계.

## 버린 대안

- **페이지 좌표 자유 배치**: 폭이 다른 기기에서 글자와 스티커가 어긋난다. 블록을 옮기면 스티커가 제자리에 남는다.
- **블록 모서리 4곳에만 붙이기**: 안전하지만 「아무 데나」가 안 된다. 블록 기준 비율이 둘을 모두 만족한다.
- **임의 CSS/스타일 속성 허용**: 검증 불가, sanitize 의존, 성능 기준을 못 세운다.
- **JS 스크롤 애니메이션(IntersectionObserver)**: 사이트의 JS 0 원칙을 깬다. 미지원 브라우저 대안으로만 남긴다.

## 감수한 트레이드오프

- 표현이 닫힌 집합 안에 갇힌다. 새 표현은 스키마 버전을 올려 추가한다 — 그것이 의도다.
- 가장 가까운 블록 판정이 애매한 위치(두 블록 사이)가 있다. 에디터가 붙는 블록을 하이라이트로 보여 준다.
- CSS 스크롤 애니메이션은 브라우저 지원이 아직 고르지 않다(미검증 — M0 스파이크). 미지원에서는 그냥 보이면 된다.
- 글꼴 서브셋 파이프라인(`pnpm fonts`)이 글 본문 글자를 포함해야 하므로 발행 · 빌드가 글꼴에 의존한다.

## 재검토 조건

- Lighthouse 기준선을 지키지 못하는 꾸미기가 나올 때 — 그 표현을 빼거나 기준선을 다시 논의.
- 2단계 사용자 업로드 스티커(용량 · 검수 · 저장 위치).
