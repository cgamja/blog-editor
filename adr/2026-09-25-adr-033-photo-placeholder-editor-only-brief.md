# ADR-033. 사진 자리는 설명만 가진 블록이고, 설명은 사진을 채운 뒤 그림의 에디터 전용 칸으로 남는다 — 둘 다 공개 글에는 나가지 않는다

- 날짜: 2026-09-25
- 상태: 제안됨 (#136, PR 머지 = 승인)
- 원천: 이슈 #136 · 사용자 결정 2026-09-25("칸을 비워 두고 이런 사진을 넣어 달라고 써 두기" · "어떤 사진이 만들어지는지 에디터에서 alt처럼 보고, 사진을 고칠 때 참고") · adr-007(AI는 이미지를 올리지 않는다) · adr-020(추가만이면 schemaVersion 유지) · adr-029(AI 이미지 생성 — 설명이 주문서) · adr-030(점검은 막지 않는다) · adr-031(부분 고치기)

## 문제 (맥락)

AI는 초안을 쓰지만 이미지를 올릴 길이 없다(adr-007). 그래서 AI가 쓴 글에는 사진이 빠지거나, AI가 외부 URL을 넣었다가 거부된다. 사용자는 두 가지를 원했다.

- 사진이 필요한 곳에 **어떤 사진인지 설명만 남기고**, 사람이 채우거나 나중에 AI 이미지 생성(adr-029 · #155)이 그 설명을 주문서로 쓴다.
- 사진이 들어간 뒤에도 그 설명을 **에디터에서 alt처럼 보고**, 사진을 바꿀 때 참고한다.

설명은 글쓴이를 위한 메모다. 독자가 보는 글이나 사이트로 나가면 안 된다.

## 결정

- **최상위 블록 `photoPlaceholder`** — `attrs: { brief, ratio? }`.
  - `brief`: 1~300자, 한 줄, 앞뒤 공백 없음. 한 문단이 넉넉히 들어가는 길이다.
  - `ratio`: `16:9` · `3:2` · `4:3` · `1:1` · `3:4` · `2:3` · `9:16`(이미지 생성 모델이 받는 범위). 없어도 된다.
  - 꾸밈 자리(글꼴 · 움직임 · 폭 · 정렬 · 스티커)는 없다. 공개 글에 나가지 않는 블록을 꾸밀 이유가 없고, 채운 그림에서 꾸민다.
- **그림(`image`)의 에디터 전용 칸 `brief`** — 같은 규칙. alt(공개 · 검색 · 접근성)와 따로다. alt는 독자가 듣는 글이고, brief는 "무엇을 찍으려 했나"다.
- **markdown `:::photo ratio=4:3`** — 컨테이너 안 꾸밈 없는 글 한 문단이 설명이다. 여러 줄은 공백 하나로 잇는다. 맨 바깥에만, 지시어 줄 없이. 콜아웃과 같은 컨테이너 문법이라 AI가 이미 익숙하다.
  - 그림의 `brief`는 markdown에 자리를 두지 않는다. 직렬화가 `losses`에 `imageBrief`로 알린다(스티커는 지시어로 옮겨지지만 사진 설명은 markdown 자리가 없다).
- **공개 글에 나가지 않는다 — 두 곳에서 막는다.**
  1. content-render는 사진 자리를 아무것도 그리지 않고, 그림의 `brief`를 어떤 속성에도 싣지 않는다(미리보기도 같다).
  2. 공개 조회(`GET /public/posts`)는 렌더 전에 `publicDocOf`(사진 자리 빼기 · 그림 brief 지우기)를 거친다.
- **발행은 막지 않고 알린다** — `checkSeo`의 `photo-placeholder`(must). 발행 확인 목록과 MCP 저장 응답이 같은 발견을 보인다(adr-030). 사진 자리를 남긴 채 발행하면 그 자리는 공개 글에서 빠진다.
- **에디터**
  - 사진 자리는 점선 상자(비율이 있으면 그 모양)에 설명을 보인다.
  - 채우기: 사진 자리를 고르고 「사진 올리기」, 사진 자리 위에 파일 놓기, 사진 자리를 고른 채 붙여넣기. 올리기가 끝나면 그 사진 자리가 그림이 된다 — 설명은 alt가 비었으면 alt로, 그리고 그림 `brief`로 옮겨진다. 그새 사진 자리가 지워졌으면 그 자리에 그림만 넣는다.
  - 그림을 고르면 폭 도구줄의 「사진 설명」 버튼에 설명 앞부분이 보이고, 누르면 고칠 수 있다. 「사진 자리로 되돌리기」는 설명을 지닌 사진 자리로 바꿔(비율은 원본 크기에 가장 가까운 값) 다른 사진으로 다시 채우게 한다.
- **부분 고치기(adr-031)** — 사진 자리의 설명은 그 블록의 찾는 글이다. 글자만 바꾸는 길은 없고 블록째 바꾸거나 지운다.

## 버린 대안

- **이미지 문법에 빈 주소(`![설명](photo:4x3)`)**: 이미지 경로 규칙(`/images/…`)과 보호 테스트(URL 허용 목록)를 건드린다. 설명이 alt와 섞여 공개 글에 새기 쉽다.
- **설명을 alt에만 두기**: alt는 독자용이라 사진이 들어가면 사진을 설명하도록 고쳐 쓴다. 그러면 "무엇을 찍으려 했나"가 사라진다. 사용자가 원한 것은 둘 다다.
- **그림 brief도 markdown으로(`:::photo` 안에 그림 두기 등)**: 왕복은 되지만 컨테이너 안 그림 · 지시어 규칙이 새로 필요하다. 부분 고치기가 범위 밖 블록을 JSON 그대로 두므로(adr-031) 잃는 경우는 AI가 글 전체를 다시 보낼 때뿐이고, 그때는 losses로 알린다. 필요해지면 새 ADR로 더한다.
- **사진 자리가 남으면 발행을 막기**: adr-030과 같은 이유로 막지 않는다. 일부러 사진 없이 발행할 수도 있다.
- **사진 자리 꾸밈 허용**: 채울 때 옮겨 줄 수는 있지만, 공개 글에 없는 블록의 꾸밈은 보이지 않는 상태를 늘린다.

## 감수한 트레이드오프

- AI가 글 전체 markdown으로 다시 저장하면 그림의 설명이 사라진다(losses로 알리고 `/blog-write`는 먼저 묻는다).
- 공개 조회는 렌더러와 같은 규칙을 한 번 더 적용한다(두 곳을 같이 고쳐야 한다) — 보호 가치가 커서 감수한다.
- 비율 7개는 작업값이다. 이미지 생성 모델의 비율이 바뀌면 늘리거나 줄인다.
- `/`·「+」 메뉴에서 사진 자리를 넣는 길은 아직 없다 — 지금은 AI(markdown)와 「사진 자리로 되돌리기」로만 생긴다.

## 재검토 조건

- 그림 설명 손실(`imageBrief`)이 자주 문제 될 때 — markdown 문법을 더한다.
- AI 이미지 생성(#155)이 비율 · 설명 형식을 더 요구할 때.
- 사람이 에디터에서 사진 자리를 직접 넣고 싶어 할 때 — 메뉴 항목을 더한다.
