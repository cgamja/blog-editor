# ADR-044. 1단계 배포는 무료로 — 에디터 API · DB · 사진은 Supabase, 에디터 화면은 Netlify, 사이트는 Cloudflare Pages

- 날짜: 2026-09-28
- 상태: 승인됨(사용자 2026-09-28, 추적 이슈 #201)
- 관계: adr-014(Lambda 진입점) · adr-004(S3 PostStore) · adr-005(AWS 서버리스)의 **배포 시점을 2단계로 미룬다**. 뒤집지 않는다 — 핸들러 · 저장소 규격은 그대로이고, 1단계 구현을 하나 더 둔다. adr-014가 버린 "Supabase Edge Functions로 먼저 배포"를 이번에 채택한다(아래 "왜 뒤집나").

## 문제 (맥락)

에디터는 하루 한 번 정도 쓰지만, 노트북이 아닌 다른 컴퓨터에서도 열려야 하고 항상 떠 있어야 한다. AWS(M4)는 비용이 들고 사용량에 비해 과하다. 사용자 결정: **1단계는 무료로 올리고, 비용이 생길 것 같으면 그때 AWS로 옮긴다.**

제약:

- 서버리스 함수는 실행이 끝나면 파일이 남지 않는다 → 글 · 설정 · 로그인 기록 · 사진을 로컬 파일에 둘 수 없다
- 사이트(simsimeestudio.com)는 Next 정적 export라 새 글은 **다시 빌드해야** 보인다(adr-001: 발행하면 빌드 신호)
- 로그인이 공개되므로 짧은 비밀번호 방어(누적 잠금)가 필요하다(원래 #33 → #203)

## 결정

| 무엇                                                    | 어디                                | 이유                                                                                                                                       |
| ------------------------------------------------------- | ----------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| 에디터 API(Hono)                                        | **Supabase Edge Functions**         | 요청 때만 켜지는 무료 함수(월 50만 호출 · 요청당 CPU 2초). Hono는 입구만 바꾸면 Lambda에서도 돈다                                          |
| DB(글 · 설정 · AI 되돌리기 · 계정 · 로그인 잠금) · 사진 | **Supabase Postgres · Storage**     | 무료(DB 500MB · Storage 1GB). 저장소 규격(계약 스위트)에 Supabase 구현을 하나 더한다                                                       |
| 에디터 화면 `editor.simsimeestudio.com`                 | **Netlify**                         | 정적 SPA. `/api/*` 리라이트로 Supabase 함수를 같은 주소처럼 써서 로그인 쿠키가 1자 쿠키로 동작. 배포는 "내보낼 때만"(무료 크레딧 월 ~20회) |
| 사이트 `simsimeestudio.com`                             | **Cloudflare Pages**                | 발행마다 재빌드. 무료 빌드 월 500 · 트래픽 무제한 · 상업 이용 가능 · 한도를 넘어도 기존 사이트는 뜬다                                      |
| 도메인                                                  | 등록은 가비아, **DNS는 Cloudflare** | 루트 주소를 Pages에 붙이려면 Cloudflare DNS가 필요                                                                                         |

- 로컬 개발은 지금처럼 Memory · File 저장소와 `@hono/node-server`. Docker Supabase는 띄우지 않는다(노트북 부하).
- AI 미리보기 이미지(`preview_post`, adr-042)는 브라우저가 필요해 **로컬 진입점에서만** 켠다. 배포에서는 "지원 안 함" 도구 오류.

### 라이브러리 게이트 — `@supabase/supabase-js` (의존성 추가는 #203에서, 사용하는 PR과 함께)

문제: 서버가 Supabase DB와 Storage를 읽고 쓴다. Supabase 함수(Deno)와 로컬 Node 둘 다에서 돌아야 한다.

## 왜 뒤집나 (adr-014가 버린 대안을 채택)

adr-014는 "이전 작업 · Deno/Node 런타임 차이 · 프록시 · 무료 플랜 일시정지 비용"을 이유로 Supabase 우선 배포를 버렸다. 그때는 **AWS 비용을 감수하는 전제**였다. 이번에는 사용자가 **비용 0**을 우선했고, 그 비용들은 아래 트레이드오프로 감수한다.

## 버린 대안

- **지금 AWS(Lambda · S3 · CloudFront)**: 비용 · 설정이 하루 한 번 쓰기에 과하다 → 2단계
- **Vercel**: 무료(Hobby)는 비상업 전용 — 회사 블로그에 약관 위험
- **Netlify에 사이트 + 에디터 둘 다**: 무료 크레딧(월 300, 배포 1회 15)을 나눠 쓰고, 발행 재빌드로 넘으면 **계정의 모든 사이트(블로그 포함)가 멈춘다**
- **Cloudflare Workers에 API**: 무료는 요청당 CPU 10ms라 markdown 변환이 넘을 수 있다
- **에디터 전부(화면까지) Supabase**: 무료 Supabase 함수는 HTML을 text/plain으로 바꾼다(커스텀 도메인은 유료 · 무료 플랜엔 없음)
- **에디터를 노트북에서만**: 다른 컴퓨터에서 써야 한다
- **사이트를 동적(SSR) · ISR로**: 방문마다 비용 · 에디터 API 장애가 블로그 장애가 된다. 글은 발행 때만 바뀌므로 재빌드가 맞다
- **사이트를 Astro로**: 이미 정적 HTML이라 SEO 충분, 46개 컴포넌트 이전 비용이 크다

## 감수한 트레이드오프

- **Deno와 Node 두 런타임**: 입구 파일 · Node 전용 코드(File 저장소 · playwright-core)를 나눠야 한다
- **무료 Supabase는 1주 비활성 시 일시 정지**: 매일 쓰면 문제없고, 멈춰도 사이트(정적)는 뜬다. 재개는 대시보드에서
- **Supabase 함수의 HTML 제한**: 에디터 미리보기 iframe을 JSON → `srcdoc`으로 바꾼다
- **AI 미리보기 이미지는 로컬 전용**
- **Netlify 배포 횟수**: 머지마다 배포하지 않고 내보낼 때만
- **세 서비스에 나뉜 설정**: Supabase · Netlify · Cloudflare 계정과 시크릿을 따로 관리한다
- 파일 저장소 · 메모리 로그인 잠금의 한계(adr-014 · adr-018)는 Supabase 구현이 맡는다

## 재검토 조건

- 어느 무료 한도에든 닿거나 비용이 생길 것 같을 때 → 2단계 AWS 이전(API 입구 Supabase → Lambda, 저장소 → S3 · DynamoDB, 데이터 한 번 복사). #3 · #84는 그때 다시 본다
- Supabase 일시 정지 · 콜드 스타트가 실제 사용에 불편할 때
- 여러 사람이 쓰게 될 때(2단계 기능, adr-007)
