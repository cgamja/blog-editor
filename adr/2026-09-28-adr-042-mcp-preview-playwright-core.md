# ADR-042. MCP 미리보기 이미지는 api의 playwright-core로 찍는다

- 날짜: 2026-09-28
- 상태: 승인됨(사용자 2026-09-28 — LIBRARY 게이트 표 보고 뒤)

## 문제 (맥락)

AI가 꾸민 결과(스티커 겹침 · 글꼴 · 폭)를 눈으로 보지 못해 스스로 고치지 못한다(#139). 렌더러(`content-render`)는 HTML · CSS만 만들고, 이미지로 바꾸려면 실제 브라우저 엔진이 필요하다. Node · Hono만으로는 안 되고, 레이아웃 · 글꼴 로딩은 엣지 케이스가 본질이라 직접 구현할 영역이 아니다.

## 결정

- `apps/editor/api`의 런타임 의존성에 `playwright-core`를 정확한 버전(루트 devDependency `@playwright/test`와 같은 1.63.0)으로 더한다. 전이 의존성 0 — 이미 lockfile에 같은 버전으로 있다(`@playwright/test`가 끌고 옴). web에는 들어가지 않는다.
- 브라우저는 e2e가 쓰는 설치본(Chromium headless shell, `pnpm exec playwright install chromium`)을 그대로 쓴다. 없으면 도구가 설치 명령을 알려 주는 오류를 낸다.
- MCP 도구 `preview_post`(읽기 전용)가 초안을 공개 렌더와 같은 HTML · CSS로 데스크톱 1280 · 모바일 390 폭에서 찍어 JPEG로 돌려준다. 한 장의 긴 변은 1568px 이하(Claude가 그 이상은 줄여 읽는다), 긴 글은 `part`로 다음 구간을 받는다 — 한 번에 두 장, 대략 2~4k 토큰(사용자 결정 2026-09-28).
- 로컬(Node) 진입점만. 배포(Lambda)에서 어떻게 찍을지는 M4 후속.

## 버린 대안

- **puppeteer-core**: 역할이 Playwright와 겹친다(같은 문제를 푸는 라이브러리는 하나 — LIBRARY 게이트 2). 전이 의존성 6, 별도 Chrome 필요.
- **의존성 없이 Chrome을 직접 실행(`--screenshot`)**: 글꼴 로딩을 기다리거나 페이지 높이를 잴 수 없어 미리보기가 부정확하고, 바이너리 경로가 취약하다.
- **클라이언트(Claude Code)가 직접 찍기**: MCP 커넥터(claude.ai · ChatGPT)에서는 브라우저가 없다. 서버가 찍어야 어디서든 같다.

## 감수한 트레이드오프

- api 런타임에 13MB(압축 해제) 패키지와 로컬 브라우저 설치가 필요하다. 로컬 전용이라 감수한다. 배포 번들에는 넣지 않는 방법을 M4에서 정한다.
- `@playwright/test`와 버전을 손으로 맞춰야 한다(둘 다 정확한 버전 고정).
- 찍는 데 브라우저를 띄우는 시간(수백 ms~1초대)이 든다.

## 재검토 조건

- M4 배포 설계 때(Lambda에서 찍을지, 별도 서비스로 뺄지, 로컬 전용으로 둘지)
- 미리보기 호출이 잦아 토큰 · 시간 비용이 문제가 될 때
