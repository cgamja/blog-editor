# /blog-seo — 초안 하나 채점하고 고치기

글 하나를 채점해 **고칠 목록을 보여 주고, 사용자가 고른 것만** 고친 뒤 다시 채점해 전후를 보여 준다. 새 글(`/blog-write` 끝)과 예전 초안 모두에 쓴다. 느리고 토큰이 들어서 매 수정마다가 아니라 초안이 다 된 뒤 · 발행 전에 쓴다. **발행은 절대 하지 않는다**(adr-007).

도구는 `blog-editor` MCP 서버의 `get_post` · `check_draft` · `update_draft` · `list_posts` · `get_writing_guide`다. "있으면"이라고 적은 인자 · 응답 칸은 도구 스키마 · 응답에 있을 때만 쓴다.

이 스킬은 Claude Code와 Codex가 같은 파일을 읽는다(Codex는 `.agents/skills/blog-seo` 링크로, adr-035). 도구마다 다른 곳만 "Claude Code면 … / Codex면 …"으로 적었다.

## 0. 준비

1. `blog-editor` MCP 도구가 보이는지 확인한다. 안 보이면 `/blog-write`의 0단계 안내(API 켜기 · 연결)를 그대로 한다.
2. 주소(slug)가 없으면 `list_posts`로 초안 목록을 보여 주고 고르게 한다.
3. `get_writing_guide`의 형식 가이드를 읽는다. 고칠 때 쓰는 markdown은 이 문법만 쓴다.

## 1. 읽기

`get_post`로 `meta`(title · description · category · keyword · draft) · `markdown` · `revision` · `losses`를 읽는다.

- **발행된 글(`meta.draft`가 `false`)이면 고치지 않는다.** MCP가 발행된 글 고치기를 거부한다(발행은 사람의 영역). 2~3단계로 채점과 고칠 목록까지만 보여 주고, "발행된 글은 에디터에서 직접 고쳐 주세요"라고 안내한다. 4단계로 가지 않는다.

## 2. 채점

1. **규칙 점수(도구):** `check_draft`에 `slug` · `markdown`(get_post 그대로) · `title` · `description` · `keyword`(있으면)를 준다. 저장하지 않고 `seo` 목록(must · should · info)이 온다. 응답에 **점수(`seoScore` 등)가 있으면** 그것도 적어 둔다. 없으면 must · should · info 개수를 점수 대신 쓴다.
2. **품질 점수(판단):**
   - Claude Code면: claude-seo가 설치돼 있으면(`claude-seo:seo-content` 에이전트 · 스킬) 제목 · 설명 · 핵심 검색어 · 마크다운을 주고 E-E-A-T · 읽기 쉬움 · 깊이 · 검색 의도 · AI 인용 적합성을 0~100으로 받는다. 초안은 공개 주소가 없으므로 URL이 아니라 **내용**으로 평가하게 한다.
   - Codex면(또는 claude-seo가 없으면): 품질 점수는 매기지 않는다. 같은 관점으로 눈에 띄는 약점만 직접 짚어 고칠 목록에 "판단" 항목으로 넣는다. 점수는 규칙 점수만 보여 준다.

## 3. 고칠 목록 — 여기서 멈춘다

번호를 붙여 보여 주고 **사용자 답을 기다린다.** 답이 오기 전에는 `update_draft`를 부르지 않는다.

- 규칙 `must` → `should` → 판단 순서. `info`는 한 줄로 묶는다.
- 항목마다: 무엇이 문제인지 · 어디(제목 · 설명 · 블록 n) · **바꿀 글 제안**(전 → 후)
- 맨 위에 지금 점수(규칙 점수, 있으면 품질 점수)
- 끝에 "전부 · 번호 골라서 · 고쳐서" 중 하나로 답하면 된다고 알린다

## 4. 반영 — 확인받은 것만

사람이 그사이 에디터에서 고쳤을 수 있다. **고치기 직전에 `get_post`로 다시 읽는다**(새 `revision` · `markdown` · `losses`).

- **글 정보(제목 · 설명 · 핵심 검색어):** `update_draft`에 `slug` · `revision` · `title` / `description` / `keyword`만 준다. 본문은 건드리지 않는다.
- **본문:** `update_draft`의 부분 고치기 `edit`를 쓴다(`{ command: "replace" | "insert_after", selection: "시작 글...끝 글", markdown }`). 고칠 부분만 보내므로 스티커 · 꾸밈이 남는다. 선택은 get_post 글에 보이는 글자 그대로(마크다운 기호 없이) 준다.
- 한 번에 하나씩 저장하고, 응답의 새 `revision`으로 다음 것을 고친다.
- 부분 고치기가 도구 스키마에 **없으면** get_post의 `markdown` 위에 고칠 곳만 바꿔 통째로 저장한다. 단 **`losses`가 비어 있지 않으면 저장하지 않는다.** 통째로 저장하면 그것(예: 스티커 3개)이 사라진다. 무엇이 사라지는지 알리고, 그래도 저장할지 사용자에게 먼저 묻는다.
- 충돌 메시지("그사이 다른 곳에서 글이 바뀌었다")가 오면 `get_post`로 다시 읽고 새 글 위에 같은 수정을 다시 적용한다.
- 부분 고치기가 "블록 일부만 덮는다"로 실패하면, 메시지대로 블록 전체를 고르거나 글자만 바꾸는 쪽으로 다시 한다.

예시 — 정보 글의 첫 소제목을 질문형으로 바꾸고 첫 문단에 검색어와 답을 넣는 새 markdown:

```example
{motion=fade-up}
## 아이랑 봄 산책은 어디로 가면 좋을까요?

아이랑 봄 산책 코스는 집에서 10~20분 거리의 공원이 가장 좋아요. 쉬는 곳이 있고 돌아오기 쉬워서 아이가 지치기 전에 끝낼 수 있어요.
```

예시 — 내부 링크를 넣는 문단(발행된 글만, `list_posts`에서 `draft: false`):

```example
아이와 걷기 좋은 길은 [동네 산책 지도 만들기](/blog/neighborhood-walk-map)에도 정리해 두었어요.
```

## 5. 다시 채점 · 보고

1. 2단계를 다시 한다(규칙 점수, 했다면 품질 점수).
2. 짧게 알린다.
   - **점수:** 전 → 후(규칙 점수, 있으면 품질 점수)
   - **고친 것:** 목록
   - **남은 것:** 고르지 않았거나 못 고친 것(이유와 함께)
   - **에디터 링크:** `update_draft` 응답의 `editorUrl`(로컬이면 `/blog-write` 7단계의 주소 바꾸기 규칙을 따른다). "미리보기로 확인하고 발행해 주세요"
   - **발행하지 않았다는 것**
