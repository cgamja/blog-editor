# markdown-validation-message Specification

## Purpose

markdown 변환 · 검증이 실패했을 때 AI가 사람 없이 스스로 고칠 수 있는 메시지 규칙(adr-007: 서버가 변환 · 검증하고 AI가 메시지를 보고 고친다). 범위는 markdown-format과 같다(MCP 입력 `check_draft` · `create_draft` · `update_draft`).

## Requirements

### Requirement: 실패 메시지는 「어디 · 무엇 · 어떻게」 세 칸이다

실패 메시지는 SHALL 항목마다 `블록 <n> (<m>줄): <규칙>(받음: "<값>") → <고친 예>` 한 줄이다. `<n>`은 최상위 블록 순번(1부터, 지시어 줄은 뒤 블록에 속한다), `<m>`은 오류 원인 토큰이 있는 markdown 원문 줄 번호다. 같은 블록 안 여러 오류는 줄 순서다. 블록 밖 오류(빈 문서 · 떨어진 지시어 · 닫히지 않은 콜아웃)는 `문서 (<m>줄): …` 형식이다. "규칙"은 허용 집합을 말하고, "고친 예"는 받은 값을 고친 실제 값이다(규칙 이름만 던지지 않는다). 값으로 고칠 수 없는 오류(빈 문서 · 닫히지 않은 콜아웃 · 외부 이미지)는 할 일 한 문장이다.

#### Scenario: 메시지에 위치 · 규칙 · 고친 예가 있다

- **WHEN** 12줄째 세 번째 블록이 `# 제목`이다
- **THEN** 메시지 문자열이 정확히 `블록 3 (12줄): 제목은 ##·###만 쓴다(받음: "# 제목") → "## 제목"`이다

#### Scenario: 빈 문서는 문서 형식으로 거부한다

- **WHEN** 빈 문자열 또는 공백 · 빈 줄만 있는 markdown을 검증한다
- **THEN** 메시지 문자열이 정확히 `문서 (1줄): 본문이 비어 있다(받음: "") → 문단 하나 이상을 쓴다`이다

### Requirement: 실패는 한 번에 전부 모아서 돌려준다

실패 응답은 SHALL 첫 오류에서 멈추지 않고 문서 전체의 오류를 원문 줄 번호 순(같은 줄이면 발견 순)으로 모두 담는다(AI가 왕복 한 번에 고치도록). 통과하면 메시지 목록은 빈 배열이다.

#### Scenario: 오류 세 개가 한 응답에 순서대로 온다

- **WHEN** 2번 블록에 `{font=comic}`, 5번 블록에 절대 URL 이미지, 7번 블록에 `javascript:` 링크가 있는 markdown을 검증한다
- **THEN** 메시지가 정확히 3개이고 블록 2 · 5 · 7 순서다

#### Scenario: 통과한 문서는 메시지가 없다

- **WHEN** 형식 가이드의 `example` 코드 블록을 이어 붙인 markdown을 검증한다
- **THEN** 메시지 목록이 빈 배열이다

실패 의미론: 해당 없음 — 순수 검증(서버 상태 없음).
