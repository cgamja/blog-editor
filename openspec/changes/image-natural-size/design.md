# Design — image-natural-size (이슈 #24)

스파이크 #4에서 꾸미기 최대 픽스처의 CLS 0.146 — 본문 `<img>`에 크기가 없어 이미지가 로드되며 아래 글을 밀어낸다. plan 3-8 "문서에는 src · alt · width · height를 저장한다". `post.css`는 이미 `figure img { width: 100%; height: auto }`라서, `<img width height>`만 나가면 브라우저가 그 비율로 자리를 먼저 잡는다(속성 → `aspect-ratio` 매핑). 새 의존성 없음.

## 결정

### 1. 이름은 `naturalWidth` · `naturalHeight`

- 가정: `width`는 이미 꾸미기 속성(블록 폭 %, D14)이라 원본 픽셀 크기는 `naturalWidth` · `naturalHeight`(DOM `HTMLImageElement.naturalWidth`와 같은 뜻)로 둔다
- 근거: plan 3-8의 `width` · `height`를 그대로 쓰면 꾸미기 `width`(%)와 겹친다
- 되돌리는 비용: 키 이름 변경 — 저장된 글이 아직 없어 스키마 · 렌더 · 변환 · 픽스처 치환

### 2. 둘 다 있거나 둘 다 없거나, 정수 1~1600

- 가정: 양의 정수, 상한 `NATURAL_SIZE_RANGE.max = 1600`(업로드가 긴 변 1600px로 줄인다 — plan 3-8). 한쪽만 있으면 거부(비율을 못 만든다)
- 근거: 닫힌 집합 — 쓸모없는 값의 자리를 만들지 않는다
- 되돌리는 비용: 상수 하나. 원본 그대로 올리는 경로가 생기면 상한을 올린다(올리는 쪽이라 옛 글은 계속 통과)

### 3. schemaVersion은 올리지 않는다

- 가정: 선택 속성 추가라 옛 문서(크기 없음)는 그대로 유효하고 마이그레이션할 것이 없다. 크기 없는 이미지는 지금처럼 크기 속성 없이 렌더된다
- 근거: plan 3-4 — 버전은 옛 문서를 새 규칙으로 옮겨야 할 때 올린다. 새 필드를 모르는 옛 코드가 새 문서를 읽는 경로는 없다(렌더 · API가 같은 배포)
- 되돌리는 비용: 크기를 필수로 바꿀 때 그때 버전 + 마이그레이션(측정할 수 없는 옛 이미지 처리가 필요)

### 4. markdown에서는 `size=<가로>x<세로>` 지시어로 보존한다

- 가정: 지시어 키 `size`(이미지 · 앱 스크린샷에만), 값 `1200x800`. 키 하나라 "둘 다 또는 없음"이 문법에서 성립한다. 직렬화 순서는 `frame` · `font` · `motion` · `width` · `size`
- 근거: `get_post`(md) → AI 수정 → `update_draft`(md) 왕복에서 크기를 잃으면 CLS가 다시 생긴다. 손실로 두면 losses 종류가 하나 늘고 MCP 병합 몫이 커진다
- 되돌리는 비용: 지시어 키 하나 · 가이드 표 한 줄
