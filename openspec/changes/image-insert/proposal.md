# image-insert (이슈 #92)

## Why

사용자 요청(2026-09-24): "이미지 추가가 없다." API(#83, ADR-021)는 머지됐다 — 서버는 검사 · 저장만 하고 줄이기는 브라우저가 한다. 이 change는 에디터 쪽이다.

## What Changes

- 넣는 길 셋: 「블록 추가」(+) 메뉴의 「이미지」(파일 고르기), 붙여넣기(클립보드 이미지 파일), 끌어다 놓기(이미지 파일)
- 브라우저 줄이기: 긴 변 1600px, WebP로 굽기(EXIF 방향 반영), 1 MiB를 넘으면 품질을 낮춰 다시 굽고 그래도 크면 이유를 보인다. 한도 안의 GIF는 원본 그대로(움직임 보존)
- 올리는 동안 자리 표시는 문서가 아니라 장식(widget)이다 — 저장 형식에 임시 노드가 없다. 끝나면 그 자리(매핑)에 image 노드를 한 번 넣는다. 자리가 지워졌으면 결과를 버린다. 실패하면 자리에 이유 · 「다시 시도」 · 「지우기」
- 대체 텍스트: 그림을 고르면 폭 도구줄에 「대체 텍스트」 입력, 비어 있는 그림에는 경고 배지(장식)
- 오류 문장: 413 · 415 · 422는 API 문장 그대로, 401은 "로그인이 필요해요"
- 플레이그라운드: vite 프록시(`/api` · `/images` → 로컬 API), `?dev` 도구에 간단한 로그인
- 올리기 한도 1 MiB를 content-schema 상수로 옮겨 API와 에디터가 같은 값을 본다

## Impact

- 새 의존성 없음(createImageBitmap · canvas.toBlob · fetch)
- 하지 않는 것: S3 presigned(M4), 이미지 자르기 · 편집, MCP 이미지 도구, 슬래시 메뉴 항목(#91 머지 뒤 후속 — 「이미지」는 블록 종류가 아니라 동작이라 INSERTABLE_BLOCKS 목록에 들어가지 않는다)
