# text-toolbar — design

## 1. 속성 합치기는 글자 조각마다

`setTextStyle(patch)`는 고른 범위의 텍스트 노드마다 지금 `textStyle` 속성에 patch를 덮어쓴 값을 새로 건다. 한 마크에 여러 속성이 들어 있으므로(ADR-020) 범위 전체에 마크 하나를 새로 걸면 조각마다 다른 크기 · 색이 사라진다. `null`은 그 속성을 지운다. 모든 속성이 비면 마크를 뗀다(스키마: 속성이 하나 이상).

값 검증은 content-schema를 그대로 쓴다 — 결과 속성을 `textStyleAttrsSchema`로 확인한다. 새 규칙을 적지 않는다.

## 2. 글꼴을 바꾸면 맞지 않는 두께는 뗀다

두께는 글꼴마다 있는 것만 허용된다(`weightFitsFont`). 두께를 고를 때 글꼴에 없으면 커맨드는 false(도구줄은 비활성 + 이유). 반대로 글꼴을 바꿔 기존 두께가 맞지 않게 되면 그 조각의 두께를 뗀다 — 글꼴 바꾸기가 두께 때문에 통째로 막히면 사용자가 이유를 찾기 어렵다.

## 3. 같은 값이면 dispatch하지 않는다

결과가 지금 문서와 같으면 true를 돌려주되 dispatch하지 않는다(#62의 같은 값 규칙) — 빈 undo 단계를 쌓지 않는다.

## 4. 마지막 색

⌘⇧H(Notion)는 마지막에 쓴 글자색 또는 배경색을 다시 건다. `setTextStyle`이 색을 걸 때 트랜잭션 meta로 알리고 작은 플러그인 상태가 기억한다. 문서가 아니라 에디터 상태라 저장 · 되돌리기와 무관하다. 기억이 없으면 false.

## 5. 코드 · 코드 블록

코드 블록은 마크를 받지 않아(`allowsMarkType`) 커맨드가 false이고 도구줄은 뜨지 않는다. 인라인 코드 마크와 `textStyle`은 스키마가 함께 허용하므로 막지 않는다.

## 6. 대비 경고

WCAG 2 상대 휘도로 글자색(없으면 본문 잉크)과 바탕(배경색, 없으면 종이 흰색)의 대비를 잰다. 4.5:1 미만이면 "읽기 어려울 수 있어요"를 보이지만 적용은 막지 않는다(ADR-020 트레이드오프). 프리셋 색 값은 design/tokens.json을 옮긴 표 하나에 둔다.

## 7. 도구줄

- 자리: 선택 시작 글자 위, 기준 틀 안에 자리가 없으면 선택 아래. 순수 함수.
- APG toolbar: role="toolbar", 로빙 tabindex, ←/→ · Home · End(`tabIndexAfterKey` 재사용).
- 버튼은 mousedown에서 기본 동작을 막아 편집 영역의 선택을 지킨다(폭 도구줄과 같다).
- 한글 조합 중에는 도구줄을 감추고 커맨드를 부르지 않는다.
- 링크 버튼은 ⌘K 팝오버를 연다 — `useLinkShortcut`이 틀에서 사용자 정의 이벤트도 받는다(팝오버 한 벌).
- 여러 값이 섞이면 드롭다운 이름이 "여러 값".
