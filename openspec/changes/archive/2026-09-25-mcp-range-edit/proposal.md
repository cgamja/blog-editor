# mcp-range-edit (이슈 #135)

## Why

사용자는 CLI에서 "중간에 ~~ 내용은 이렇게 바꿀래", "도시락 문단은 Gaegu로"처럼 말해 그 부분만 고치길 원한다(2026-09-25, 노션 MCP처럼). 지금 `update_draft`는 글 전체 markdown을 다시 받는다. 그러면 긴 글은 느리고, 한 문단을 고쳐도 다른 블록이 마크다운 왕복을 거친다. 특히 스티커는 마크다운에 자리가 없어서(#134 전) 고칠 때마다 모든 블록의 스티커가 사라진다.

## What Changes

- **content-convert `editDocRange(doc, edit)`**: 범위를 집어 문서의 일부만 고치는 순수 함수다.
  - 범위는 `"시작 글...끝 글"` 한 모양이다(`…`도 받는다). `...`가 없으면 그 글자 자체가 범위다. 글자는 블록 안 보이는 글자로 찾고, 마크다운 기호는 빼고 본다.
  - `replace`
    - 범위가 한 글자 블록 안에 있고 새 markdown이 꾸밈 없는 문단 하나(또는 빈 글)면 **그 글자만** 바꾼다. 블록의 앞뒤 글자 · 마크 · 꾸밈 · 스티커는 그대로다.
    - 범위가 한 코드 블록 안이고 새 글이 코드 펜스가 아니면 그 글자만 새 글 그대로 바꾼다.
    - 그 밖에는 범위가 걸친 최상위 블록들(목록 · 인용 · 콜아웃 · 코드 블록이면 그 전체)을 새 markdown의 블록들로 바꾼다. 범위가 그 블록들 전체(앞뒤 공백 제외)를 덮지 않으면 실패한다. 빈 글이면 그 블록들을 지운다.
    - 최상위 블록 하나를 블록 하나로 바꾸면 스티커를 새 블록으로 옮긴다(마크다운에 스티커 문법이 생기기 전까지).
  - `...`로 나눠 찾지 못하거나 여러 곳이면 글자 그대로 다시 찾는다(글에 말줄임표가 든 경우).
  - `insert_after`: 범위 끝이 든 최상위 블록 뒤에 새 markdown 블록들을 넣는다.
  - 범위 밖 최상위 블록은 다시 직렬화하지 않으므로 그대로다.
  - 찾지 못하거나 두 곳 이상이면 고칠 방법이 담긴 메시지를 돌려준다.
- **MCP `update_draft` 확장**(도구 6개 유지): `markdown`(전체) · `edit`(부분) · 둘 다 없음(글 정보만) 중 하나로 고친다. revision · 초안 확인 · SEO 결과 첨부는 그대로다. 도구 설명 · 형식 가이드 · 서버 instructions에 사용 예를 넣는다.
- ADR-031.

## Impact

- `update_draft`의 `markdown`이 선택 인자가 된다. 전체 markdown으로 부르는 기존 호출은 그대로 동작한다.
- 하지 않는 것:
  - 스티커 마크다운 문법(#134)
  - 표 칸 안 범위(표는 #130 브랜치에 있다 — 합칠 때 글자 블록 찾기가 표 칸도 따라간다)
  - 에디터 화면 변경
