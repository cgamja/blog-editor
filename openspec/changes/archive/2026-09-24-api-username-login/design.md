# Design — api-username-login

## 1. 아이디 비교: 앞뒤 공백을 빼고 대소문자는 무시한다

`Admin`과 `admin`을 다른 계정으로 둘 이유가 1단계에 없고, 로그인 폼의 대문자 자동 변환 · 붙여넣기 공백으로 실패하는 쪽이 더 흔하다. 기존 email 비교와 같은 규칙이라 동작도 그대로다. 2단계에 가입이 생기면 가입 시점에 같은 정규화로 중복을 막는다.

## 2. 로컬 env 해석을 순수 함수로 뺀다

`serve.ts`는 최상위 await와 서버 기동이 있어 테스트할 수 없다. 규칙(비밀번호는 평문 · 해시 중 정확히 하나, 아이디 기본값, 비밀 생성)을 `local-config.ts`의 `readLocalConfig(env)`로 옮겨 테스트하고, `serve.ts`는 그 결과로 앱을 띄우기만 한다.

- `ADMIN_PASSWORD`와 `ADMIN_PASSWORD_HASH`가 둘 다 있거나 둘 다 없으면 시작하지 않는다 — 어느 쪽이 쓰였는지 모르는 상태를 만들지 않는다.
- 평문은 시작할 때 `hashPassword`로 해시하고, 메모리 계정 행에는 해시만 들어간다(원문을 계정 테이블에 두지 않는 규칙은 그대로).
- 평문의 길이는 검사하지 않는다 — 로컬 서버는 루프백(127.0.0.1)에만 열리고 TLS도 없어, 비밀번호 강도가 막아 줄 위협이 같은 기기 밖에 없다. `hash-password.ts`의 20자 최소 규칙은 배포용 해시를 위한 것이라 그대로 둔다.

## 2-1. 레포 루트 `.env`를 읽는다 — 새 의존성 없이

사용자는 아이디 · 비밀번호를 `.env`나 개인 문서로 관리한다(2026-09-24). `serve.ts`가 시작할 때 Node 내장 `process.loadEnvFile`로 레포 루트 `.env`(gitignore됨)를 읽는다. Node 26에서 확인한 동작: 셸에 이미 있는 값이 이기고, 파일이 없으면 `ENOENT` — 그것만 조용히 넘기고 다른 읽기 오류는 드러낸다. dev 스크립트는 `apps/editor/api`에서 돌기 때문에 경로는 작업 디렉터리가 아니라 `serve.ts` 파일 기준으로 푼다. 비밀번호에는 코드 기본값을 두지 않는다 — 없으면 ".env에 ADMIN_PASSWORD=…"를 알려 주며 멈춘다. `.env.example`은 보호 패턴이라 만들지 않고 PR 본문에 예시를 둔다.

## 3. SESSION_SECRET이 없으면 시작할 때 만든다(로컬만)

로컬 편의. 무작위 32바이트라 강도 문제는 없고, 대가는 재시작하면 세션이 끊기는 것뿐이다 — 기동 로그에 한 줄로 알린다. 값을 주면 그 값을 쓰고, 32바이트 미만이면 기존대로 `createApp`이 거절한다.

## 4. 배포(M4)는 이 경로를 쓰지 않는다

D8의 방어는 "긴 무작위 비밀번호"가 전제다. 짧은 비밀번호(`1234`)로 공개 서버를 열면 1만 번 시도로 뚫린다. M4 진입점(Lambda)은 해시만 받고, 짧은 비밀번호를 계속 쓰려면 잠금 카운터(5회 실패 → 15분 잠금, D8 재검토 조건)를 같이 넣는다 — 그 결정은 [#33](https://github.com/cgamja/blog-editor/issues/33)으로 넘긴다.
