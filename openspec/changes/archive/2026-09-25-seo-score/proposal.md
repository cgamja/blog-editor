# seo-score (이슈 #148)

## Why

#138(PR #146) 이후 저장할 때마다 SEO 점검 목록이 붙는다. 하지만 목록만 보고는 고친 뒤에 **좋아졌는지** 한눈에 알 수 없다. 사용자는 claude-seo처럼 점수를 보고 고치는 흐름을 써 왔다. 이 change는 새 글이든 수정이든 계속 SEO를 챙기게 하는 흐름의 첫 층이다: 점수 → 저장 직후 훅(#149) → `/blog-seo`(#150) → 에디터 패널(#151).

같은 경로에 버그가 하나 있다. `checkSeo`가 글자를 모을 때 강제 줄바꿈(`hardBreak`, #153)을 빈 글자로 읽는다. 그래서 줄 앞뒤 글자가 붙고("첫 줄" + "둘째 줄" → "첫 줄둘째 줄"), 첫 문단 글자 수가 줄바꿈 수만큼 적게 세진다.

## What Changes

- **content-schema `scoreSeo(findings)`**
  - 발견 목록으로 0~100 점수를 계산하는 순수 함수다.
  - 규칙 하나당 등급별로 한 번씩 깎는다(must 25 · should 10 · info 3). 0 아래로는 내려가지 않는다.
  - 점수는 저장하지 않고 매번 계산한다.
  - 감점 표는 이름 붙인 상수로 둔다.
  - web(#151 에디터 패널)이 같은 함수를 쓰도록 content-schema에서 export한다.
- **`checkSeo` 글자 모으기**: `hardBreak`를 줄바꿈 한 글자로 읽는다.
- **MCP**: `check_draft` · `create_draft` · `update_draft`의 성공 응답에 `seoScore`를 싣는다.
  - `seo`가 `null`이면 `seoScore`도 `null`이다.
  - 도구 수는 6개 그대로다.
- **web**: 발행 확인 대화상자의 "검색 노출 점검"에 점수를 보인다.
- 형식 가이드 §4에 감점 표를 적는다.
- ADR-034를 쓴다.

## Impact

- MCP 쓰기 도구 응답에 `seoScore` 필드가 더해진다. `seo`는 그대로 발견 목록이다.
- 하지 않는 것:
  - 점수로 저장 · 발행을 막는 것. adr-030대로 알리기만 한다
  - 점수를 저장하거나 기록하는 것. 매번 계산한다
  - 글 품질(E-E-A-T · 깊이) 점수. `/blog-seo`(#150)에서 한다
  - 에디터 실시간 패널. #151에서 한다
