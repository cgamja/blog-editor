# web-post-list (이슈 #96)

## Why

web 뼈대(#93) 위에 첫 화면이 없다. 로그인은 최소 폼이고, 로그인하면 자리 표시 화면만 보인다. 글 목록이 있어야 편집(#97) · 가져오기 · AI로 쓰기(#98)로 들어갈 길이 생긴다. 세션 확인도 글 목록 API(`GET /api/posts`)를 빌려 쓰고 있어, 목록 화면이 생기면 같은 요청이 두 번 뜻을 갖는다.

## What Changes

- API `GET /api/session`: 세션이 있으면 204, 없으면 401. 계약 표에 먼저 넣고 `api/openapi.json`을 다시 만든다. web의 세션 확인이 이 경로로 바뀐다
- 앱 틀(`AppShell`): 왼쪽 메뉴(글 · AI 연결 · 설정 · 로그아웃) + 본문 자리(`<Outlet/>`). 로그인이 필요한 화면은 이 틀 안의 자식 라우트로 붙는다
- 로그아웃: `DELETE /api/session` → 쿼리 캐시를 비우고 세션을 로그인 필요로 → 로그인 화면
- 로그인 화면: A안(종이 위 카드 — 로고 · 아이디 · 비밀번호 · 로그인). 틀린 로그인은 API 문장 + 고정 안내("여러 번 틀리면 잠시 잠겨요")
- 글 목록(`/`): 탭 전체 · 초안 · 발행됨(개수, `?tab=`), 표(제목 · 카테고리 · 상태 · 고친 날), "AI가 올린 초안" 포스트잇, 버튼 AI로 쓰기 · 가져오기 · 새 글, 아래 안내문
- 빈 목록 A안: 포스트잇 "아직 글이 없어요" + 새 글 · 가져오기 · AI로 쓰기. 탭만 비면 한 줄
- 대화상자 자리: 가져오기 · AI로 쓰기 버튼은 `?dialog=import|write-ai`를 연다. 대화상자는 라우터가 `PostListPage`의 `dialogs` prop으로 넘긴다(#98이 채운다). 넘긴 것이 없으면 버튼이 비활성

## Impact

- API 라우트 1개 추가(계약 · 라우트 목록 테스트가 함께 바뀐다). 로그인 · 잠금 동작은 그대로
- 디자인과 다른 점: 로그인 실패 문장의 "남은 횟수 · 잠금 시간"은 보이지 않는다 — API가 잠김 여부를 응답으로 드러내지 않는 것이 보안 요구(api-session "틀린 로그인은 계정 유무를 드러내지 않는다" · 잠금 판정 숨김)라 고정 안내로 바꾼다. 메뉴 아래 워크스페이스 이름은 계정 정보에 이름이 없어 뺀다. 카테고리는 설정 값(이름표)이 없어 값을 그대로 보인다
- 하지 않는 것: 편집 화면(#97), 가져오기 · AI로 쓰기 대화상자 · AI 연결 · 설정 화면(#98), 목록 검색 · 페이지 나누기
