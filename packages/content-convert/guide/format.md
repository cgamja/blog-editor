# 글 형식 가이드 (markdown 입력 문법)

`get_writing_guide`가 돌려주는 형식 가이드다. 문법마다 예시 하나. `check_draft` · `create_draft` · `update_draft`에 보내는 markdown이 대상이다.

**markdown은 원본이 아니라 입력이다.** 저장 형식은 문서 JSON이고 markdown은 입력 전용이다 — 네가 보낸 markdown은 변환 · 검증을 지나 그 JSON이 된다. 그래서 아래에 없는 문법은 "무시"가 아니라 "실패"다 — 실패 메시지를 보고 고쳐서 다시 보내면 된다. 제목 · 설명 · 카테고리 같은 메타는 markdown 안에 쓰지 않는다(도구 인자로 따로 준다).

## 1. 표준 문법 — 되는 것

| 쓰고 싶은 것 | 문법                                       | 규칙                                                                                                 |
| ------------ | ------------------------------------------ | ---------------------------------------------------------------------------------------------------- |
| 문단         | 빈 줄로 구분한 글                          | 문단 안 줄바꿈은 공백 하나가 된다                                                                    |
| 제목         | `## 큰 제목` · `### 작은 제목`             | `#` 하나(h1)와 `####` 이하는 안 된다                                                                 |
| 목록         | `- 항목` · `1. 항목`                       | 둘 다 안쪽 목록 중첩 가능. 항목 = 문단 하나 + 안쪽 목록. 번호는 1부터                                |
| 인용         | `> 글`                                     | 인용 안에는 문단만                                                                                   |
| 코드         | ` ```ts ` … ` ``` `                        | 언어는 소문자로 시작, 소문자 · 숫자 · `+#.`만(`ts` `bash` `c#`). `-`는 안 된다                       |
| 구분선       | `---`                                      |                                                                                                      |
| 이미지       | `![대체 글자](/images/record-screen.webp)` | `/images/<소문자·숫자·하이픈>.webp\|png\|jpg\|jpeg\|gif`만. 절대 URL은 안 된다. 대체 글자 200자 이내 |
| 굵게         | `**글자**`                                 |                                                                                                      |
| 기울임       | `*글자*`                                   |                                                                                                      |
| 인라인 코드  | `` `글자` ``                               |                                                                                                      |
| 링크         | `[글자](https://…)`                        | `http(s)://` · `mailto:` · `/`로 시작하는 내부 경로만. `javascript:`는 실패                          |

예시 — 이것 하나가 위 표를 전부 쓴다:

````example
## 육아비서 기록 기능

기록은 **한 번의 탭**으로 끝난다. 자세한 흐름은 [도움말](/help/record)을 보라.

### 기록 종류

- 수유 · 수면 · 기저귀
  - 세부 항목은 *선택*이다
- `memo` 필드는 자유 글

1. 앱을 연다
2. 기록 버튼을 누른다

> 기록은 언제든 고칠 수 있다.

```ts
const record = { type: "feeding", at: Date.now() };
```

---

![기록 화면](/images/record-screen.webp)
````

### 같은 결과가 되는 변형 — 받는다

`*`/`+` 글머리 · `1)` 구분자 · `_기울임_` / `__굵게__` · `~~~` 펜스 · 들여쓰기 코드 · autolink `<https://…>` · 문단 안 줄바꿈(공백 하나로).

### 안 되는 것 (변환 실패)

`# 제목`(h1) · `#### 제목` · 표(헤더 줄 `| a | b |` + 구분선 `|---|---|`) · 취소선(`~~`) · 각주 · 할 일 목록(`- [ ]`) · HTML(`<div>` · `<br>`) · 절대 URL 이미지 · `javascript:` 링크 · 인용 안의 제목 · 목록 안의 코드 블록 · 줄 끝 공백 둘이나 `\`로 강제 줄바꿈 · 1이 아닌 시작 번호(`3.`) · 글자와 섞인 인라인 이미지 · 링크/이미지의 title(`"…"`).

## 2. 확장 문법 — 이 서비스에만 있는 것

### 콜아웃 `:::callout`

`tone`은 `note` · `tip` · `warning`. 생략하면 `note`. 안에는 문단과 목록만. 반드시 `:::` 줄로 닫는다 — 안 닫으면 여는 줄 번호로 실패한다. 콜아웃 안 콜아웃, 목록 · 인용 안 콜아웃, 빈 콜아웃은 실패.

```example
:::callout tone=tip
처음이라면 수유 기록부터 시작해 보세요.

- 하루 3번이면 충분하다
- 시간은 대략이면 된다
:::
```

> 이 컨테이너 문법은 스파이크 #2 결과에 따라 ` ```callout ` 펜스 문법으로 바뀔 수 있다.

### 블록 속성 지시어 `{key=value}`

블록 **바로 앞 줄**(빈 줄 없이)에 한 줄. 그 블록 하나에만 적용되고, 글자로 남지 않는다. 최상위 블록에만 — 목록 · 인용 · 콜아웃 **안**에서는 실패. 같은 키 두 번, 지시어 두 줄 연속, 뒤에 블록이 없는 지시어도 실패.

| 키       | 값                                                           | 되는 블록                          |
| -------- | ------------------------------------------------------------ | ---------------------------------- |
| `font`   | `pretendard` · `jua` · `gaegu`                               | 문단 · 제목 · 목록 · 인용 · 콜아웃 |
| `motion` | `fade-in` · `fade-up` · `slide-left` · `slide-right` · `pop` | 모든 블록                          |
| `width`  | `%` 없는 정수 `25`~`100`                                     | 이미지 · 앱 스크린샷               |

```example
{font=jua motion=fade-up}
## 베타 테스트를 시작합니다

이 문단에는 지시어가 적용되지 않는다.
```

지시어 줄은 문단을 끝낸다 — 문단 글자 바로 아래 줄에 쓰면 그 다음 블록에 붙는다. 코드 펜스 안의 `{…}` 줄은 그냥 코드 글자다. 문단 첫 줄을 우연히 `{a=b}`로 시작해야 하면 `\{a=b}`로 쓴다.

### 앱 스크린샷 `{frame=app}`

이미지 앞에 `{frame=app}`를 두면 폰 프레임을 씌운 앱 스크린샷이 된다. 대체 글자가 캡션(120자 이내)이 된다. `width`와 같이 쓸 수 있다.

```example
{frame=app width=60}
![오늘의 수유 기록 화면](/images/record-screen.webp)
```

### 스티커 — markdown 문법 없음

스티커는 사람이 에디터에서 끌어다 붙인다. `{stickers=…}`처럼 쓰면 실패한다. 정의 밖의 키(`color` 등)와 값(`font=comic`)도 실패다.

## 3. 검증 실패 메시지

실패하면 오류를 **전부 한 번에** 원문 줄 번호 순으로 돌려준다. 한 줄 형식:

```text
블록 <n> (<m>줄): <규칙>(받음: "<값>") → <고친 예>
```

`<n>`은 최상위 블록 순번(1부터, 지시어 줄은 뒤 블록에 속한다), `<m>`은 오류 원인이 있는 markdown 줄 번호. 빈 문서 · 떨어진 지시어 · 안 닫힌 콜아웃처럼 블록 밖 오류는 `문서 (<m>줄): …`로 온다.

```text
블록 3 (12줄): 제목은 ##·###만 쓴다(받음: "# 제목") → "## 제목"
블록 5 (20줄): 이미지는 /images/<이름>.<확장자> 경로만(받음: "https://cdn.example.com/a.png") → 이미지 줄을 지우고 사람에게 업로드를 요청한다. 이미 올린 "/images/…" 경로만 쓸 수 있다
블록 7 (31줄): 링크는 http(s)·mailto·내부 경로만(받음: "javascript:alert(1)") → "[글자](https://example.com)"
```

메시지대로 고쳐서 `check_draft`로 다시 검증하면 통과한 문서는 메시지가 비어 있다. 이미지는 AI가 올릴 수 없다 — 사람이 에디터로 올린 `/images/…` 경로만 쓴다.
